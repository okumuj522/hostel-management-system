# Hostel Booking System

Hostel administration dashboard and student portal built with React, Vite, Django REST Framework, and SQLite.

## Run the complete system

From the workspace root, activate the Python environment:

```powershell
.\venv_new\Scripts\Activate.ps1
```

Install backend dependencies and apply migrations once:

```powershell
cd .\hostel_system
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
```

Install frontend dependencies and start Django plus the frontend from one command:

```powershell
cd ..\frontend
npm.cmd install
npm.cmd run start
```

Open `http://127.0.0.1:8000/`. The React app and API are served by Django from the same address; the API is available under `/api/`. In PowerShell, use `npm.cmd` if script execution policy blocks `npm`.

The administrator dashboard accepts Django staff or superuser accounts. Student registration links to an existing student record, matching its student number and phone number. Create or verify student records in the administrator dashboard before students register.

For frontend-only development with Vite, `npm.cmd run dev` is also available while Django runs on port 8000; Vite proxies `/api` requests to Django. This development mode uses two servers, while `npm.cmd run start` serves the complete system on one address.

To override the same-origin API URL, create `frontend/.env` with:

```text
VITE_API_URL=/api
```

## Verify changes

Run backend tests and checks:

```powershell
cd .\hostel_system
python manage.py test hostel
python manage.py check
python manage.py makemigrations --check --dry-run
```

Run frontend lint and production build:

```powershell
cd .\frontend
npm.cmd run lint
npm.cmd run build
```

The API requires token authentication for protected hostel resources. Administrator sign-in/out routes are `/api/auth/login/` and `/api/auth/logout/`. Student register/login routes are `/api/auth/student/register/` and `/api/auth/student/login/`; the student profile is available at `/api/student-profile/`.

Applications remain pending until an administrator reviews them. Allocation and room assignment are administrator-controlled, and the API checks room capacity before an active allocation is created. Run `python manage.py migrate` after pulling changes to add student-account and maintenance ownership fields.

## Deploy on Render

The repository includes a Render Blueprint (`render.yaml`) and a Dockerfile that build and serve the frontend and Django API together. The Blueprint provisions free web and PostgreSQL services for a demo. Render's free web service sleeps after inactivity, and its free PostgreSQL database expires after 30 days; upgrade the database before expiry to preserve its data.

1. Push the repository to GitHub.
2. In Render, choose **New → Blueprint**, connect this GitHub repository, enter a strong password when prompted for `DJANGO_SUPERUSER_PASSWORD`, and approve the services described in `render.yaml`.
3. Wait for the first deployment to finish. The container applies database migrations on startup, then Render's initial deploy hook creates the administrator account.
4. After the initial deploy hook succeeds, remove `DJANGO_SUPERUSER_PASSWORD` from the web service's environment variables; it is only needed to create the first administrator.
5. Open the Render service URL. The student portal and admin dashboard are served from the same address.

Render supplies `RENDER_EXTERNAL_HOSTNAME`; Django uses it for host and CSRF validation. `DJANGO_SECRET_KEY` is generated by Render, debug mode is disabled, static assets are served by WhiteNoise, and PostgreSQL is configured through `DATABASE_URL`.
